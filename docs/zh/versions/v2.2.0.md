# v2.2.0

> 面向"生产稳定性 + 开发体验"的加固版本，修复多项边界崩溃并增强无服务器场景的优雅降级。

## 版本亮点

- 修复 plugin-logger 在 ICE candidate 为 null 时的空指针崩溃。
- 信令服务器不可达时，推流端保留本地摄像头预览而非全部资源销毁。
- 新增 `streamingstatechange: 'failed'` 状态，暴露信令失败事件。
- 修复 React StrictMode 下组件重复挂载导致 PeerConnection 悬挂的问题。
- 新增 `ErrorBoundary` 组件，单组件异常不再导致整个示例页面白屏。
- 防护 Google Translate 等浏览器扩展改写 DOM 引发的 React reconciliation 冲突。

## 详细更新

### ICE Candidate 空值防护

- `plugin-logger` 的 `onIceCandidate` 钩子增加 candidate 空值检查。
- WebRTC 规范中 ICE 收集完成时浏览器会触发 candidate 为 null 的事件，此版本前直接读取 `.candidate` 属性会抛出 TypeError。

### 信令失败优雅降级

- `RtcPublisher.start()` 内部对 `createSession` 异常做分层捕获。
- 信令失败时调用 `resetSession()` 清理悬挂的 PeerConnection，但 **不释放本地 MediaStream**。
- 调用方收到 `start() === false` 后可继续使用本地 video 预览，仅推流上屏失败。

### 状态机扩展 — 新增 `failed` 状态

- `streamingstatechange` 事件类型新增 `'failed'` 状态值。
- `onStreamingStateChange` Hook 参数类型同步扩展。
- 业务方可监听 `failed` 事件实现自定义的失败提示与恢复策略。

### React 示例加固

- 新增 `ErrorBoundary` 组件，分别包裹推流端面板与拉流端面板。
- `StreamPublisher` / `StreamPlayer` 增加 `useEffect` 清理函数，组件卸载时自动 `destroy()` 实例。
- 修复 React StrictMode 下 mount → unmount → mount 循环导致的资源泄漏。

### Google Translate DOM 冲突防护

- `App.tsx` 根元素添加 `translate="no"` 与 `class="notranslate"` 标记，跳过浏览器翻译扩展。
- 避免翻译插件改写真实 DOM 后 React reconciliation 执行 `removeChild` 找不到节点。

## 兼容性与迁移提示

- `streamingstatechange` 事件新增 `'failed'` 值。已实现 exhaustive check 的业务方建议补充分支处理。
- `plugin-logger` 的 Hook 类型签名无 breaking change，`onIceCandidate` 现在会收到 candidate 为 null 的回调（ICE 完成标志），建议业务侧也做空值防护。
- React 示例已自动处理组件卸载清理逻辑，升级后无需额外适配。
